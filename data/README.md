# Dataset

This directory contains a 10-scene subset for running the pipeline. The full dataset is not
included because of its size. It can be regenerated with any reference RTE solver as long as
the arrays, shapes and index conventions below are respected.

## Directory layout

```text
data/
├─ front/data1/
│  └─ med_XXXX.npz                 # homogeneous background scenes
├─ after/data1/scenes/
│  └─ med_XXXX.npz                 # inhomogeneous scenes
├─ after/data1/bg/
│  └─ med_XXXX.npz                 # paired background references
└─ after/cache1/
   └─ XXXX/
      ├─ D.npy
      ├─ Yb.npy
      ├─ Pb.npy
      ├─ Pf.npy
      ├─ meta.npz
      └─ static.npz
```

`scenes/med_XXXX.npz` and `bg/med_XXXX.npz` are paired by the same `XXXX`.

## Grid and array conventions

- Spatial grid: `x_i = y_i = i / 40`, `i = 0..40`.
- Direction set: 24 directions defined by `code/consts.py` (`VC`, `WQ`).
- Angular field axes: `(pulse, x, y, direction)`.
- Scalar flux axes: `(pulse, x, y)`.
- Scalar flux is the quadrature sum over directions:
  `PHI[p, i, j] = sum_k WQ[k] * I[p, i, j, k]`.
- `IDX[p] = (side, node, direction)`:
  - `side = 0,1,2,3` for left, right, bottom, top;
  - `node = 0..40` along that side;
  - `direction` indexes the 24 directions.
- All files use the same `IDX` ordering; pulse `p` in `Y`, `PHI` and `ID` refers to `IDX[p]`.

## Front scenes

`data/front/data1/med_XXXX.npz` describes one homogeneous background medium:

| Key | Shape | Dtype | Meaning |
|---|---|---|---|
| `P` | `(3,)` | float32 | `(sigma_t, omega0, g)` |
| `IDX` | `(N,3)` | int16 | pulse index triples |
| `Y` | `(N,41,41,24)` | float32 | `log(I + 1e-12)` angular field |
| `PHI` | `(N,41,41)` | float32 | scalar flux |
| `ID` | `(N,41,41)` | float32 | analytic ballistic term |
| `TE` | `(K,)` | int32 | test pulse indices |

`N` is the number of unit pulses in the scene. `TE` is optional; when omitted, the loader
uses its default 9:1 split.

## After scenes

`data/after/data1/scenes/med_XXXX.npz` describes one inhomogeneous scene:

| Key | Shape | Dtype | Meaning |
|---|---|---|---|
| `OCC` | `(41,41)` | bool | occupied-node mask |
| `P_BG` | `(3,)` | float32 | background `(sigma_t, omega0, g)` |
| `P_OBJ` | `(3,)` | float32 | object `(sigma_t, omega0, g)` |
| `IDX` | `(N,3)` | int16 | pulse index triples |
| `Y` | `(N,41,41,24)` | float32 | full-field `log(I + 1e-12)` |
| `PHI` | `(N,41,41)` | float32 | full-field scalar flux |
| `ID` | `(N,41,41)` | float32 | analytic ballistic term |
| `GEO` | `(1,)` | unicode | optional geometry description |
| `TE` | `(K,)` | int32 | test pulse indices |

`data/after/data1/bg/med_XXXX.npz` has the same `IDX` and `Y/PHI/ID` layout for the
homogeneous background reference of the same scene.

Derived arrays such as `MUT`, `MUS` and `BG_OF` may be present; training and evaluation use
`OCC`, `P_BG`, `P_OBJ`, `IDX`, `Y`, `PHI` and `ID`.

## After-network cache

`data/after/cache1/XXXX/` is generated by:

```powershell
python code\after\prep_cache.py
```

| File | Shape | Dtype | Meaning |
|---|---|---|---|
| `D.npy` | `(100,41,41,24)` | float16 | `Y_full - Y_bg` |
| `Yb.npy` | `(100,41,41,24)` | float16 | background `Y` |
| `Pb.npy` | `(100,41,41)` | float32 | background scalar flux |
| `Pf.npy` | `(100,41,41)` | float32 | full-field scalar flux |
| `meta.npz` | — | — | `IDX/OCC/P_BG/P_OBJ/GEO/TE` |
| `static.npz` | — | — | `tokP/tokR/qryP/qryR` |

Only `static.npz` depends on the interface sampler. Rebuild it alone with:

```powershell
python code\after\prep_static.py
```

Cache generation options:

| Variable | Meaning |
|---|---|
| `CACHE` | cache root, default `data/after/cache1` |
| `S_DIR` | scene directory |
| `B_DIR` | background directory |
| `MEDIA` | scene range, e.g. `0,20` |
| `FORCE` | `1` overwrites existing files |

The cache scripts only read the precomputed scene files; they do not call a reference solver.

## Generating the full dataset

The full dataset is too large to distribute here. To regenerate it with any reference solver,
produce the arrays above with exactly the same grid, direction set, quadrature weights and
`IDX` ordering, then place the files in the layout shown at the top of this document.

For a new scene, ensure that:

1. `scenes/med_XXXX.npz` and `bg/med_XXXX.npz` share the same `IDX`;
2. `Y` and `PHI` are computed on the 41×41 grid with the 24-direction quadrature;
3. `PHI` is the quadrature sum of `exp(Y) - 1e-12` over directions;
4. `D` and the cache are regenerated with `code/after/prep_cache.py`.
